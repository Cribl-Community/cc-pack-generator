Debug: Add Sample to existing cisco-test pack

Each step uses its own unique sample ID (DbgSmN) so they don't conflict. Run 1+2 first (create metadata), then 3-8 (try writing content), then 9 (deploy), then 10+11 (verify).

Step 1: POST metadata-only to pack (creates DbgSm1)

POST /m/seLab/p/cisco-test/system/samples — {id, sampleName, isTemplate} no items

Step 2: POST metadata-only to global (creates DbgSm2)

POST /m/seLab/system/samples — {id, sampleName, isTemplate} no items

Step 3: POST with context.events to pack (THE UI METHOD)

POST /m/seLab/p/cisco-test/system/samples — {sampleName, context: {events: [...]}}

Step 4: POST with context.events to global

POST /m/seLab/system/samples — {sampleName, context: {events: [...]}}

Step 5: PUT full object to pack (targets DbgSm1)

PUT /m/seLab/p/cisco-test/system/samples/DbgSm1 — full sample with items[]

Step 6: PUT full object to global (targets DbgSm2)

PUT /m/seLab/system/samples/DbgSm2 — full sample with items[]

Step 7: POST multipart file upload to pack

POST /m/seLab/p/cisco-test/system/samples — multipart/form-data with file

Step 8: POST multipart file upload to global

POST /m/seLab/system/samples — multipart/form-data with file

Step 9: Commit + Deploy

Step 10: List pack samples + check /content (pack-scoped)

Lists all samples in pack, then GETs /content for each

Step 11: Same samples — check /content (GLOBAL scope)

Same IDs from pack list, but fetches via /m/seLab/system/samples/{id}/content

Step 12: Cleanup — delete ALL debug samples
